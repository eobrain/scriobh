Over the years I have tried many different technologies for self-hosting my blog, currently at http://eamonn.org.

Up until now, I have used either a fully dynamic online database-driven architecture or a static site generated by an offline site generator. But now, for this blog, I am using a fully static online architecture.

| Fully Dynamic Online | Static-Manual Offline  | Fully Static Online |
| :---- | :---- | :---- |
| ![dynamic CMS and content][1] | ![manual CMS, content static][2] | ![CMS static, content static][3] |
| Authoring is **easy** | Authoring is **difficult** | Authoring is **easy** |
| Blog has **poor** performance and reliability | Blog has **good** performance and reliability | Blog has **good** performance and reliability |


When I started blogging, the only self-hosted solutions were fully dynamic PHP-based systems like WordPress. The lack of scalability, the hassle of maintaining my own server or VPS, and dealing with the never-ending security vulnerabilities of PHP made this less and less attractive.

In this architecture, an online database-driven CMS[^1] provides both an editing interface and the presentation of the blog to the end user.

## Static-Manual Offline Era

As soon as the idea of static site generation emerged, I made the switch.

In this architecture, an offline site generator takes the content from the writer and generates the blog content for distribution via a CDN[^2].

For hosting the content, this was a huge improvement in both cost and performance. The marginal cost was essentially free because static content of this modest size can be hosted under free plans on a variety of platforms, including Firebase Hosting, GitHub Pages, and Netlify. And because the content is highly cacheable and runs on a highly distributed CDN, it is extremely high performance, loading into browsers with low latency.

However, authoring the content was awkward on these static site schemes. Generally, it meant having to edit files in a Git repo, which added a lot of friction to the process.

## Fediverse Fully Dynamic Online Era

Several years ago I realized that the authoring friction of the static site-generator systems meant that I was neglecting to update my blog. At the same time, I was participating in the Fediverse, mostly via the short-form Mastodon system, and wanted my blog to be part of the Fediverse.

So I switched over to a self-hosted version of [https://writefreely.org/](https://writefreely.org/), which was a return to the world of fully-dynamic online hosting, albeit much more modern, efficient, and secure. It promised the ability to join the Fediverse in a long-form format, with the convenience of online authoring.

The new blogging platform was successful because the ease of writing posts encouraged me to publish more often.

However, it turned out that the Writefreely integration into the Fediverse was very incomplete. It was clumsy for anyone to follow the blog from a Mastodon account, so very few people did, and the blog posts just appeared as links in feeds, not with the full text or even a truncated summary.

And I had to maintain a cloud server to keep the blog running 24/7.

## Fully Static Online Era

In my day job, my work as a programmer has totally changed in the last few months, because of the advent of highly-capable AI coding agent software. At work we use an internal Google version of Antigravity, and I wanted to compare this to Claude Code, by trying Claude on a project.

So, having become dissatisfied with my blog platform, I decided to unleash Claude on it.  Or to be precise, a combination of Gemini and Claude, because one best practice that is emerging in agent-driven software development is to separate the planning phase from the execution phase.  So first I gave Gemini the general outline of the requirements and asked it to generate a detailed prompt for Claude Code. The request was well specified; I pointed to the existing [eamonn.org](http://eamonn.org) web site as an exemplar (minus the Fediverse support). I also added the requirements for a fully static deployment and an authoring UI.

I was expecting an architecture where the authoring part would require a server.

To my surprise, Gemini came up with a fully static design in which a static web app distributed via a CDN provides an in-browser editing interface that securely updates GitHub, from which static content is synced back to the CDN. This takes advantage of the fact that, using only JavaScript, the web app can control GitHub on the author’s behalf using a GitHub "Personal Access Token" to ensure only the owner could authorize changes.

Giving this Gemini-generated design to Claude Code as a prompt generated a first working version of the new blog within about an hour, viewable on GitHub Pages, with just a few interventions by me. Then, with some follow-up, I was able to set up Netlify as a production CDN, where I can set my custom domain.
